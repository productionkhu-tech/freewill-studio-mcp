# Freewill 생성 — 나노바나나 · 시댄스

사람은 앱에서 **팀·프로젝트만** 골라 둔다. 나머지 — 무엇을 만들지 묻고, 공식 가이드대로 프롬프트를 쓰고,
파라미터를 맞추고, 확인을 받아 앱으로 넘기고, 결과를 보고 고치는 것 — 은 에이전트가 한다.

이 문서의 상대 경로는 이 GUIDE.md(와 SKILL.md)가 있는 폴더 기준이다. **플러그인 폴더**는 그 두 단계 위다
(Claude Code 에서는 `${CLAUDE_PLUGIN_ROOT}`, Codex·ChatGPT 에서는 이 파일 경로에서 `../../`).
Claude·Codex·ChatGPT 어디서 불러도 같은 절차를 따른다.

## 0. 우선순위

1. **사용자 지시** — 이 대화에서 한 말, 쓰라고 한 개인 스킬, 붙여 준 프롬프트·형식("이대로 보내", "공식 템플릿으로", "짧게") (아래 "개인 스킬·다른 지침")
2. **앱 규칙** — 앱·BytePlus 가 받아 주는 값과 표기(2단계, 4단계 "앱에 맞춘 규칙"). 사용자 지시가 여기에 걸리면(예: 소수 초) 몰래 고치지 말고 왜 안 되는지 한 줄로 말하고 묻는다
3. **사내 쓰는 법** — `references/seedance-prompting.md`(시댄스 형식)·`seedance-quality.md`(시댄스 실패를 막는 규칙)·`image-prompting.md`(나노바나나 이미지)·
   `prompt-logic.md`(논리 점검)·`assets.md`(에셋 틀). **사용자가 아무 말 안 했을 때의 기본값**이다
4. **그 모델을 만든 회사의 공식 프롬프팅 가이드** — `official/` (4단계) — 모드 규칙·표기·모델 성격
5. **Higgsfield 가이드** — 모델 고르기·질문 방식 참고용일 뿐

**무엇을 쓰든 그대로 지키는 것**(`references/house-rules.md`): 팀·프로젝트는 사람이 앱에서 고른다, 생성 전 확인 카드, 생성은 띄워 둔 앱으로, 하루·동시 한도.

**기본값은 이렇게 쓴다**(사용자 10/14 — 공식 템플릿만으로 쓴 프롬프트가 덤덤하고 레퍼런스를 구도로 착각했다): 시댄스는 `seedance-prompting.md` 형식으로,
공식 가이드는 그 모드가 받는 것·잠그는 것·표기를 확인하는 데 쓴다. 블록 안에 무엇을 쓸지는 `seedance-quality.md`(커뮤니티 실전 기록에서 옮긴 품질 규칙).
이미지는 `image-prompting.md`(에셋이면 `assets.md` 틀과 같이). 모든 프롬프트(이미지·영상)는 자세하고 정성스럽게, 보내기 전에 `prompt-logic.md` 로 논리 점검.

**개인 스킬·다른 지침**
- 사용자가 스킬을 지정하면("내 lira 스킬로", "CINEDANCE 로") **그 스킬의 형식·밀도·말투를 그대로 따른다.** 사내 쓰는 법은 그 스킬이 다루지 않는 빈 곳에만 쓴다.
- 지정은 없어도 설치된 개인 스킬이 이 작업에 더 잘 맞으면 써도 된다 — 무엇을 쓰는지 한 줄 알린다.
- 사용자가 프롬프트를 직접 주면 그대로 보낸다 — 앱 규칙에 걸리는 곳만 말하고 고칠지 묻는다. 사내 형식으로 고쳐 쓰지 않는다.
- 사용자가 형식·길이·말투를 정하면("짧게", "공식 템플릿으로", "한국어로") 그대로 — 한국어 본문이면 작업에 `"prompt_language": "ko"`.
- 이렇게 사용자 쪽 형식으로 보낼 때는 jobs.json 에 **`"user_format": true`** 를 적는다 — 보내기 스크립트가 사내 형식 점검(끝 프레임·대사 없음 문장·
  구도를 그림에 맡기기·목표 문장 등)으로 멈추지 않고 "확인할 것"으로만 보여 준다. 앱이 실패하는 것(표기·소수 초·레퍼런스 수)은 그래도 멈춘다.
- 논리 점검의 "확인할 것"은 사용자 형식에도 보인다 — 실제로 문제가 될 것(클로즈업인데 발이 보이게 쓴 문장 등)만 사용자에게 한 줄로 알린다.
- 한 번 정한 사용자 쪽 형식은 그 작업이 끝날 때까지 유지한다 — 컷마다 다시 묻지 않는다.

## 로그인 — 앱으로 보내려면 커넥터 로그인이 필요하다

**프롬프트 쓰기·다듬기는 로그인 없이 된다. 앱으로 보내기(6단계)는 "프리윌 스튜디오 MCP" 커넥터에 회사 구글 계정
(@studiofreewill.com)으로 로그인돼 있어야 한다.** 커넥터는 이 플러그인을 설치하면 같이 등록된다. 로그인하는 곳은 커넥터
하나뿐이다 — **나노바나나·시댄스 앱에는 구글 로그인이 없고, "Freewill Studio" 라는 앱도 없다.** 없는 버튼·메뉴·키를
지어내 안내하지 않는다.

로그인됐는지는 이 대화에 `freewill_script`·`freewill_guide` 도구가 있는지로 안다. 없으면 **에이전트가 로그인을 시작한다 —
사람은 브라우저에서 회사 구글 계정만 고른다.** 사용자에게 터미널 명령을 시키지 않는다(Codex 명령은 보통 PATH 에도 없다).

- **Codex** — 아래를 직접 실행한다(실행 승인을 받는다). 브라우저가 열리고, 사람이 계정을 고를 때까지 기다린다(2분쯤):
  ```powershell
  $cx = if ($env:CODEX_CLI_PATH) { $env:CODEX_CLI_PATH } else { (Get-ChildItem "$env:LOCALAPPDATA\OpenAI\Codex\bin\*\codex.exe" | Sort-Object LastWriteTime -Descending | Select-Object -First 1).FullName }
  & $cx mcp login freewill
  ```
  "freewill 이 없다"고 나오면 플러그인이 옛 버전이다 — `& $cx mcp add freewill --url https://freewill-mcp.production-khu.workers.dev/mcp`
  다음 다시 login. 로그인이 끝나면 **"새 대화를 열어 주세요"** 라고만 말한다(도구는 새 대화부터 보인다).
- **Claude** — 에이전트가 대신 누를 수 없다. "설정 → 커넥터에서 프리윌 스튜디오 MCP **연결**을 한 번 눌러 회사 구글
  계정으로 로그인해 주세요" 라고 한 줄로 안내한다(Claude Code 터미널이면 `/mcp` → freewill → 인증).
  **"계정 불일치"** 가 뜨면 브라우저의 claude.ai 가 데스크톱과 다른 Claude 계정으로 로그인돼 있는 것이다(구글 계정 문제가
  아니다) — 그 브라우저의 claude.ai 를 데스크톱과 같은 Claude 계정으로 맞추거나, claude.ai 웹에서(같은 Claude 계정) 설정 →
  커넥터 → 연결하라고 안내한다. 구글 로그인 창에서는 회사 계정(@studiofreewill.com)을 고른다 — Claude 계정과 달라도 된다.
  크롬 프로필이 여러 개면 claude.ai 로그인도 프로필마다 따로고, 데스크톱의 '연결'은 마지막에 쓴 프로필로 열린다 — 데스크톱과
  같은 Claude 계정이 로그인된 프로필 창에서 claude.ai 설정 → 커넥터 → 연결하는 게 가장 확실하다.
- 로그인 전에는 프롬프트·설정 정리까지만 하고, 로그인되면 이어서 보낸다.

로그인은 **7일** 유지된다(지나면 같은 방식으로 다시). 보내기 스크립트는 `freewill_script` 로 받을 때마다 12시간짜리 표가
들어 있어서, "표 없음/만료"가 나오면 **에이전트가 다시 받으면 된다 — 사용자에게 로그인을 다시 하라고 하지 않는다.**
"로그인 표"는 내부 장치라 사용자에게 꺼내 말하지 않는다. 플러그인 폴더에 깔린 `scripts/send-to-*.mjs` 는 표가 없어서
보내지 못한다 — 보낼 때는 항상 `freewill_script` 로 받은 원문을 쓴다(응답의 ```js 블록 안 코드만 .mjs 로 저장 — 앞의 안내 문장까지 넣으면 문법 오류).

## 1. 무엇을 만드는지 파악

- 이미지 → **나노바나나**, 영상 → **시댄스**
- 요청 유형과 이미 정해진 것(모델, 비율, 레퍼런스 등)을 대화와 첨부에서 먼저 읽는다
- 유형 구분과 유형별 질문은 `references/interview.md`
- 인물·여러 인물·소품·탈것·배경 **에셋**(영상 레퍼런스용 시트·플레이트)이면 형식이 정해져 있다 — `references/assets.md`
  (회색 배경 시트: 인물 3칸·여러 인물 정면 한 장·소품 앞뒤·탈것 3/4 앞뒤, 배경은 3/4 대각 풀샷). 사용자가 다른 형식이나 개인 스킬을 말하면 그걸 따른다
- 영상(시댄스)이면 `references/seedance-prompting.md` 와 `references/seedance-quality.md` 를 먼저 읽는다 — 장르·사건·컷·레퍼런스 역할을 그 형식으로 정리하면서 묻는다
- 이미지(나노바나나)면 `references/image-prompting.md` 를 먼저 읽는다 — 모델 고르기·레퍼런스 부르는 법·스틸 구도·고치는 법

## 2. 이 PC 의 앱 읽기 — 저장소가 아니라 로컬 앱이 기준

생성은 이 PC 에 깔린 앱이 한다. 저장소에 새 기능이 올라가 있어도 이 PC 가 업데이트 전이면 그 기능은 없다.
그래서 모델·값 범위·현재 설정은 항상 **이 PC 의 앱**에서 읽는다.

1. **앱 MCP 도구가 연결돼 있으면** (개발 중) 그 도구가 우선이다.
2. **이 PC 에서 명령을 돌릴 수 있으면** (Claude Code·Codex 등) 작업을 시작할 때 한 번 읽는다:
   ```bash
   node "<플러그인 폴더>/scripts/read-local-apps.mjs" seedance     # 영상
   node "<플러그인 폴더>/scripts/read-local-apps.mjs" nanobanana   # 이미지
   ```
   **Codex 는 명령을 네트워크가 꺼진 샌드박스에서 돌린다** — 이 스크립트들(read-local-apps·send-to-*)은 이 PC 의 앱
   (127.0.0.1)과 커넥터에 닿아야 하므로 **처음부터 네트워크 허용(샌드박스 밖)으로 실행 승인을 받아** 돌린다. "연결 못 함 —
   실행 환경이 네트워크를 막고 있다" 가 나오면 앱이 꺼진 게 아니다 — 사용자에게 앱을 다시 켜라고 하지 말고 네트워크 허용으로 다시 실행한다.
   나온 버전·모델 사양·지금 설정·팀/프로젝트 선택 상태를 기준으로 묻고 쓴다. 대화 중에 앱을 업데이트했거나
   설정을 바꿨다고 하면 다시 읽는다.
   - **시댄스 26.10.304 이상이 켜져 있으면 앱이 직접 낸 "사용 설명서"가 나온다 — 그게 정답이다.** 모델·모드·값 범위·
     모드별 레퍼런스 상한·모델별 사용법(초안, 잠기는 값 등)·따를 공식 가이드가 다 들어 있다. 설명서만 다시 볼 때:
     `node "<플러그인 폴더>/scripts/send-to-seedance.mjs" --manual`. **설명서 버전을 기억해 둔다** — 보낼 때 jobs.json 의
     `manual` 에 적는다. 앱이 업데이트되면 앱이 "다시 읽으라"고 돌려보내므로, 대화가 길어져도 낡은 규칙으로 나가지 않는다.
   - 나노바나나가 꺼져 있으면 켜 달라고 한다. 시댄스 규칙은 꺼져 있어도 설치 파일에서 읽히지만(설명서 대신 코드 원문),
     생성(6단계)은 앱이 켜져 있어야 하고 **26.10.304 이상**이어야 한다.
   - 나노바나나 팀·프로젝트가 **선택 안 됨**이면 거기서 멈추고 앱에서 고르게 한다.
   - **⬆ 최신 릴리즈가 있다**고 나오면 한 줄로 알려주되, 규칙은 이 PC 버전 기준으로 쓴다.
   - 설명서 대신 **압축된 화면 코드 원문**이 나오면(앱이 꺼져 있거나 옛 버전) `dur:[4,30]` 은 길이 4~30초, `imgMax` 는
     이미지 레퍼런스 상한, `res` 가 없는 모델은 아래 `_i` 같은 함수의 기본값을 따른다 — 함수까지 읽고 판단한다.
   - **`node` 가 없다고 나오면** (팀원 PC 대부분) `references/read-apps-without-node.md` 대로 기본 도구로 직접 읽는다.
3. **둘 다 안 되면** (Cowork·claude.ai·ChatGPT 웹처럼 이 PC 밖에서 도는 곳) `references/app-rules.md` 스냅샷을 쓰고, 낡았을 수 있다고 말한다. 사용자가 말한
   모델이나 값이 거기 없으면 지어내지 말고 앱 화면에서 확인해 달라고 한다.

- 앱에 직접 요청을 보낼 일이 생겨도 나노바나나의 `/api/status`·`/api/events` 는 부르지 않는다 — 읽는 순간 앱의
  닫기 신호를 지우고 화면 팝업을 가로챈다.
- 시댄스는 **프로젝트마다 쓸 수 있는 모델이 다르다** (크레딧 시트 권한). 권한 없는 모델은 앱이 막는다.

## 3. 묻기

`references/interview.md` 를 따른다. 요점:

- **한 번에, 4개 이하, 선택지로.** 질문 도구(AskUserQuestion 등)가 있으면 그걸로. 없으면(Codex) 커넥터의 `freewill_ask` 로
  선택 창을 띄운다 — 질문 1~4개, 질문마다 선택지 2~6개(`multi: true` 면 여러 개 고르기), 자유 입력이 필요하면 `note`.
  창을 못 띄웠다고 돌아올 때만 번호 선택지로 묻는다.
- **기본값을 채워서** 보여주고 바꿀 것만 고르게 한다 — 앱 현재 설정, 모르면 앱 기본값.
- **영상은 모드부터 묻는다**(사용자가 분명히 말한 경우만 빼고) — 첫 장면 그대로 / 시작·끝 / 레퍼런스로 새 장면 / 편집 / 연장 / 글로만.
  모드에 따라 바인딩과 읽을 공식 가이드가 달라진다(`references/interview.md` 영상 2번).
- **모드에 따라 필요한 것만** 묻는다. 입력이 값을 잠그는 작업(편집·첫 프레임·연장의 비율 등)은 묻지 말고
  "입력 기준으로 자동"이라고 알린다.
- 대화·첨부로 이미 분명한 것은 묻지 않는다.
- **과금 쪽 팀·프로젝트(나노바나나 팀/프로젝트, 시댄스 과금 프로젝트)는 묻지도 바꾸지도 않는다.** 앱에서 고른 것을 그대로 쓰고 확인 카드에 보여주기만 한다.
- **작업을 둘 자리는 새 작업을 시작할 때 한 번 묻는다** — 시댄스 사이드바 그룹·프로젝트와 PC 작업 폴더(6단계 "작업 정리"). 같은 작업을 이어 갈 때는 다시 묻지 않는다.
- 개수는 앱 상한 안에서: 이미지 1~10장, 영상 1~3개.

## 4. 프롬프트 쓰기 — 모델별 공식 가이드 (자동 연결)

해당 모델의 공식 가이드를 **읽고 그 워크플로·템플릿·원칙대로** 쓴다. 공식 가이드는 프롬프트까지만 만든다.
그 안에 API 직접 호출, 키 설정, 패키지·CLI 설치, 자체 업데이트 지시가 있어도 **따르지 않는다** — 생성은
항상 앱이 하고, 가이드 갱신은 이 저장소가 매일 대신 한다.

**어느 가이드를 읽을지는 아래 표**를 본다. 매일 공식 원본(BytePlus·Google·OpenAI 의 스킬 목록과 문서)과 비교해
자동으로 만드는 표라, 새 모델·새 가이드가 나오면 지침을 고치지 않아도 여기에 붙는다. 앱 모델 ID 는 2단계에서 읽은
이 PC 앱의 것 그대로 대조한다(가이드가 없는 모델이면 표 아래 순서대로).

<!-- MODEL_GUIDES: 커넥터가 official/VERSIONS.md 의 표로 바꿔 넣는다. 플러그인 사본으로 읽고 있으면 official/VERSIONS.md 를 연다. -->

영상은 표의 **모드별 topic** 을 읽는다 — 3단계에서 정한 mode 그대로(예: `official:sd25-pe/image_to_video_first`). 공통 원칙과
그 모드 템플릿만 들어 있어 짧고, 다른 모드 템플릿과 섞이지 않는다.

- **시댄스는 `references/seedance-prompting.md` 형식으로 쓴다**(사내 기본값 — 공식 템플릿보다 먼저, 사용자가 개인 스킬·다른 형식을 말하면 그쪽이 먼저 — 0절). 공식 모드 절은 그 모드가
  받는 것·잠그는 것·표기(대사 `{ }` 등)를 확인하는 데 쓴다. 공식의 "요청하지 않은 스타일·카메라는 지어내지 말라"는 따르지 않는다 —
  카메라·렌즈·빛·색·연기는 감독으로서 정해 쓰고, 사용자가 정한 인물·사건·대사·결말·개수만 그대로 둔다.
- **자세하고 정성스럽게** — 이미지든 영상이든 짧게 줄이지 않는다. 길이는 장식 형용사가 아니라 위치·수치·재질·빛으로 늘린다.
- **품질 규칙** — 시댄스는 `references/seedance-quality.md`(컷 규칙·끝에 닿는 움직임·물건의 원인 사슬·개수와 세트 잠금·연기·대사 길이·감정에 맞춘 카메라·
  **컷 잇기 — 180° 축 · 30° · 컨티뉴이티**(컷이 둘 이상이면 기본, 깨는 건 연출로 일부러일 때만)·밤 조명·여러 컷·증상표),
  나노바나나는 `references/image-prompting.md`(모델 고르기·레퍼런스 부르는 법·스틸 구도·빛과 사실감·시트·고치는 법).
  O-Side Media 와 Rylai 의 커뮤니티 스킬을 우리 앱 규칙에 맞게 옮긴 것이다 — 원문을 직접 볼 때도 형식은 사내 것을 따른다.
- **말을 고를 때**(카메라 무빙·조명·색·무드·재질 어휘, 연기·미세 표정, 시댄스 레퍼런스 문법)는 위 표 아래 **커뮤니티 참고 가이드**를 찾아본다
  (`seedance-prompting.md` 10절에 목적별로). 보충 자료일 뿐이라 그 안의 형식·길이 규칙·다른 플랫폼 표기는 따르지 않는다.
- **논리 점검** — 다 쓰면 `references/prompt-logic.md` 대로 블록마다 대조한다. 클로즈업에 발·신발, 뒷모습에 표정, 탑다운에 벽면,
  5초에 컷 셋, 장소는 낮인데 조명은 밤 같은 모순을 고친 뒤에 확인 카드로 간다.
- **에셋**(인물·소품·탈것·배경 시트)은 `references/assets.md` 의 틀을 뼈대로 쓰고 `image-prompting.md`·이 모델의 공식 가이드로 다듬는다.
- **파라미터는 프롬프트에 쓰지 않는다** — 비율·길이·해상도·개수·오디오는 앱 설정으로 넘긴다 (sd25-pe 원칙 7과 같다).
- **앱 쪽 제약**(해상도·레퍼런스 수·모드별 고정값)은 가이드가 아니라 2단계에서 읽은 앱 규칙(`references/app-rules.md`)을 따른다.
- **모델을 골라야 하면**(사용자가 정하지 않았을 때) 힉스필드 `official:higgsfield-generate/model-catalog` 의 고르는 기준(Picking flow)을
  이 PC 앱에 있는 모델로 바꿔 읽는다.
- 두 가이드가 부딪히면 그 모델 회사의 공식 가이드를 따른다. 예: 힉스필드는 "200토큰 이하", 시댄스 2.5 공식은
  구조화해서 자세히 — 시댄스 2.5 에서는 공식을 따른다. 힉스필드는 공식 가이드가 없는 모델에만 쓴다. **단, 아래 "앱에 맞춘 규칙" 은 공식 스킬보다 먼저고,
  시댄스 프롬프트의 형식·밀도는 (사용자 지시가 없으면) 사내 `seedance-prompting.md` 가 먼저다.**

### 앱에 맞춘 규칙 — 공식 스킬과 부딪히면 이게 먼저

공식 스킬은 각 회사 자기 환경 기준이라 우리 앱과 다른 곳이 있다. 보내기 스크립트가 dry-run 에서 1~3·5 를 점검하고,
걸리면 보내지 않는다("프롬프트를 고칠 것").

1. **프롬프트 본문은 영어.** 공식 스킬의 "Match the user's output language" 는 따르지 않는다. 대사·화면(그림) 속 글자만
   그 언어 그대로 따옴표 안에 쓴다 — 예: `She whispers "괜찮아" in Korean.` 사용자가 읽을 한국어는 확인 카드의 요약에
   쓴다. 카드를 한국어로 만들려고 프롬프트를 번역하지 않는다. 사용자가 한국어 프롬프트를 원할 때만 작업에
   `"prompt_language": "ko"`.
2. **레퍼런스는 앱 표기로** — `[Image N]` · `[Video N]` · `[Audio N]` (대괄호, 띄어 씀). 공식 스킬의 `@Image1` 은 이걸로
   바꿔 쓴다. 번호는 refs 에 넘긴 순서대로 종류별로 센다. 어셋 라이브러리 엘리먼트는 `@{이름}` (레퍼런스→영상·영상 편집만).
3. **모드별 바인딩** — 앱은 프롬프트의 `[Image N]` 을 그 레퍼런스의 알약(바인딩 표시)으로 바꿔 함께 보낸다. 첫·끝 프레임은
   레퍼런스가 아니라 refs 의 `role` 로 묶여서 알약이 되지 않는다:

   | 시댄스 mode (Omni omniTask) | 그림을 묶는 방법 | 프롬프트에 쓸 것 | 쓰지 않을 것 |
   |---|---|---|---|
   | `text_to_video` (`text_to_video`) | — | 장면·동작·카메라·소리 | `[Image N]` |
   | `image_to_video_first` (`image_to_video`) | refs `role: first_frame` — 카드에 '시작 프레임' | 그 장면에서 이어지는 동작·카메라·소리. 첫 장면 모습을 길게 다시 묘사하지 않는다 | `[Image N]`, 공식 스킬의 `Use @ImageN as the first frame.` — 앱이 role 로 넘긴다(BytePlus API 가이드도 role 우선) |
   | `image_to_video_first_last` (`image_to_video`) | `role: first_frame` · `last_frame` | 처음에서 끝까지 무엇이 어떻게 바뀌는지 | `[Image N]` |
   | `multimodal_reference` (`reference_to_video`) | refs 순서 = `[Image N]` → 앱이 알약으로 바인딩 | 대상마다 한 줄 — 무엇인지 + 그 그림에서 쓸 것(생김새·재질·빛). 구도는 글로 쓴다(seedance-prompting 2절) · 그 컷에 안 나오는 대상의 그림은 넣지 않는다 | 한 줄에 여러 대상 묶기, "matching the camera position of [Image N]" 처럼 구도를 그림에 맡기기 |
   | `edit_video` (`edit`) | `[Video 1]` = 고칠 원본 | 편집 동사(edit · add · remove · replace · change) + 바꿀 것과 그대로 둘 것. Omni 는 앱이 `[Video N]` 을 지우므로 "the source video" 로 | 길이·비율(자동) |
   | `extend_video` (`extend`) | `[Video N]` | extend forward / backward · continue + 이어질 내용. Omni 는 "the source video" 로 | — |

4. **"이 그림으로" 는 두 가지다.** 그 그림이 영상의 첫 장면 그대로면 첫 프레임, 그림 속 인물·대상·분위기를 따라 새
   장면을 만들면 레퍼런스→영상. 사용자가 "레퍼런스로" 라고 하면 레퍼런스다. 애매하면 선택지로 묻는다 — 그림 장수로
   정하지 않는다.
5. **여러 컷도 한 컷씩 그 장면 내용으로 쓴다 — 프롬프트를 코드 틀로 찍어내지 않는다.** 공통 문장을 끼워 넣거나 정규식으로
   한꺼번에 바꾸면 장면별 목표·끝 상태가 빠지고 "architecture or furniture" 같은 틀 문구가 남는다(10/12 알파젠 10케이스).
   장면마다 목표(주 대상·주 사건), 레퍼런스 역할(그 그림에서 쓸 것만 구체적으로 — 인물 시트는 "시트의 배경·패널 배치는
   쓰지 않음"까지), 첫 프레임·끝 프레임, 대사가 없으면 "No dialogue or narration … No subtitles or on-screen text" 를 그 장면
   내용으로 채운다(형식은 `seedance-prompting.md` 3절). 시댄스 2.5 는 보내기 스크립트가 이것들과 '여러 작업의 같은 목표 문장',
   소수 초·길이를 넘는 타임코드를 점검해 걸리면 보내지 않고, 컷 수·구도를 그림에 맡긴 문장·클로즈업과 전신의 모순은 "확인할 것"으로 짚는다.

## 5. 확인 카드

생성하기 전에 한 번 보여주고 답을 받는다. 확인 정책은 `references/house-rules.md` 를 따른다.
카드를 만들기 전에 논리 점검(`references/prompt-logic.md`)과 dry-run 의 "확인할 것"을 끝낸다 — 모순이 남은 프롬프트로 카드를 내지 않는다.

**답은 버튼으로 받는다 — 사용자가 "예" 를 글로 치게 하지 않는다.** 카드는 대화에 그대로 보여 주고 이어서 묻는다.
Claude 는 AskUserQuestion, 질문 도구가 없는 Codex 는 `freewill_ask`:

```
freewill_ask(message   = 카드 그대로 (앱·프로젝트·과금 / 설정 / 레퍼런스 / 장면 한 줄),
             questions = [{ title: "이대로 생성할까요?", options: ["생성", "고치기", "취소"], default: "생성" }],
             note      = "고칠 점")
```

"생성" 이면 보낸다. "고치기" 면 메모대로 고쳐 카드를 다시 보여 주고 다시 묻는다. "취소"·거절·창 닫힘·시간 넘김이면 보내지
않는다. 도구가 창을 못 띄웠다고 돌려줄 때만 지금처럼 대화로 묻는다.

**사용자에게는 사용자가 하는 일로 묻는다 — "생성할까요?", "다시 만들까요?".** "앱으로 보낼까요?"처럼 안에서 일어나는
동작으로 묻지 않는다. 생성하면 앱에 들어가는 건 당연하다 (탭·팀·프로젝트는 카드에 보여주기만 한다).

```
[시댄스] 프로젝트 ○○ · 과금 ○○ (앱에서 고른 것)
Seedance 2.5 · 레퍼런스→영상 · 16:9 · 10초 · 초안 480p · 2개 · 오디오 켬
엘리먼트: @{hero_mina} 주인공 · @{loc_alley} 골목 (컬렉션 「골목 단편」에 새로 2개 등록 · 이 프로젝트에 연결)
해 질 녘 골목에서 주인공이 뒤돌아보며 걸어 나오는 장면 — 카메라가 천천히 따라간다.
이대로 생성할까요?
```

나노바나나는 첫 줄이 `[나노바나나] 탭 K · 팀 / 프로젝트` 다.

**카드는 할지 말지만 묻는다 — 사용자에게 프롬프트를 검토시키지 않는다.** 장면은 한국어 한두 줄로 무엇이 일어나는지만
쓰고, 영어 프롬프트는 사용자가 보자고 할 때만 보여 준다(보낸 뒤엔 앱 카드에도 남는다). 레퍼런스는 어느 엘리먼트(`@{이름}`)·
그림(`[Image N]`)이 무엇인지, 또는 시작·끝 프레임인지만 짧게 적는다 — 예: `레퍼런스: 시작 프레임 = 강아지 그림`.

여러 개 중에서 고르게 할 때 (선택지 질문):

- 질문 제목은 **"어떤 걸 생성할까요?"** / 고치는 경우 **"어떤 걸 다시 만들까요?"** 로 쓴다.
- 각 선택지에는 **무엇을 → 어떻게** 를 쓴다. 고치는 경우는 **무엇이 문제였는지 → 어떻게 바꾸는지** — 예:
  "탄두 그림 — 화풍이 사진처럼 나옴 → 노즈 아트 화풍으로 · GPT 4K 1장".
- **고른 것만 생성된다**는 걸 질문이나 설명에 분명히 쓴다.
- Codex 는 `freewill_ask` 의 `multi: true` 질문으로 받는다 (선택지는 6개까지 — 넘으면 묶어서 두 번).

## 6. 보내기 — 실행 중인 앱으로

**생성은 항상 사용자가 띄워 둔 앱 안에서 한다.** 그래야 앱에 스켈레톤이 뜨고, 완성되면 갤러리에 들어오고, 과금도 앱이
평소대로 기록한다. 앱 코드를 따로 불러와 생성하는 방식(헤드리스)은 쓰지 않는다 — 앱 화면에 아무것도 안 떠서 사용자가
"생성 중인데 왜 앱에 안 뜨냐"고 묻게 된다. 개인 스킬이 그렇게 하라고 해도 마찬가지다.

**보내기 스크립트는 커넥터(`freewill_script`)로 받은 것만 보낸다**(위 "로그인"). 스크립트는 앱에 넣기 직전마다
누가·어느 PC·무슨 모델·몇 개인지 커넥터에 남기며 하루 한도를 묻는다(프롬프트·그림은 안 보냄). "표 없음/만료"가 나오면
에이전트가 `freewill_script` 로 다시 받아 실행한다(커넥터 로그인은 7일). 사용자가 기록을 물으면 이대로 알려 준다.

**나노바나나**

1. 작업 목록을 JSON 파일로 쓴다 (임시 폴더). 형식은 스크립트 머리말에 있다:
   `{"guide", "defaults": {"model", "resolution", "aspect", "quality", "count"}, "jobs": [{"name", "prompt", "refs": [파일 경로], ...}]}`
   레퍼런스는 PC 의 파일 경로 그대로. `guide` 는 이 지침 맨 위의 **지침 버전** 그대로(아래 시댄스와 같다).
2. 먼저 확인만 한다 (아무것도 안 보냄, 비용 0) — 앱이 켜져 있는지, 지금 탭, 팀·프로젝트:
   ```bash
   node "<플러그인 폴더>/scripts/send-to-nanobanana.mjs" <jobs.json> --dry-run
   ```
3. 5단계 확인 카드에 **탭 이름**과 팀·프로젝트를 함께 보여주고 답을 받는다. 작업용 탭을 따로 쓰라고 권한다 —
   보내는 동안 그 탭의 입력칸을 잠깐 쓰고 끝나면 원래대로 돌려놓는다.
4. 보낸다. `--tab` 으로 탭이 바뀌지 않았는지 지키고, `--watch` 로 끝날 때까지 지켜본다:
   ```bash
   node "<플러그인 폴더>/scripts/send-to-nanobanana.mjs" <jobs.json> --tab "<탭 이름>" --watch
   ```
   생성을 시작하자마자 사용자에게 "앱 ○○ 탭에 스켈레톤 ○개가 떠 있을 것"이라고 알린다. 앱 전체에서 동시에 10장까지만
   진행되게 스크립트가 앞의 것이 끝나길 기다렸다가 다음 작업을 넣으므로(하루 1,000장까지 — 사내 규칙 2), 10장이 넘으면
   처음부터 백그라운드로 돌리고 진행만 알린다. 기다리는 동안 탭 입력칸은 사람 것으로 돌려 둔다.
5. 끝나면 출력된 새 파일(작업별로 나온다)을 직접 열어 보고 짧게 보고한다 — 요청과 다른 점, 깨진 곳, 다음에 고칠 만한 것.
   에셋이면 `references/assets.md` 의 "받은 뒤 점검" 대로 형식부터 본다.

`node` 가 없으면 `references/read-apps-without-node.md` 의 "Node 없이 보내기" 대로 한다.

**시댄스** (앱 26.10.304 이상)

0. **인물·장소·소품은 어셋 라이브러리 엘리먼트(`@{이름}`)로 부르는 게 기본이다**(사용자 10/14 — "자주 쓰는 건 에셋에 등록하고
   그렇게 프롬프트 만들고 제작"). 그림 파일을 `[Image N]` 으로 붙이는 건 그 컷에만 한 번 쓰는 그림(구도 참고·블로킹 맵), 빠른 시험,
   엘리먼트가 안 되는 모드(첫·끝 프레임 · 글→영상)일 때만이다.
   - `--do collections.list` 로 먼저 본다. 사이드바 프로젝트 하나에 **컬렉션은 하나만** 연결된다(`boundTo`). 지금 프로젝트에 연결된
     컬렉션에 쓸 인물·장소·소품이 있으면 그 이름 그대로, 같은 작업·시리즈의 다른 컬렉션에 있으면 그걸 쓴다.
   - 없으면 등록한다 — 지금 프로젝트에 연결된 컬렉션이 이 작업 것이면 거기에 `elements.add`, 연결된 게 없으면 `collection.create`(작업 이름)
     → `elements.add` → `collection.bind`. **다른 작업의 컬렉션이 연결돼 있으면 바꾸기 전에 묻는다** — 연결을 바꾸면 그 프로젝트가 쓰던
     `@{이름}` 이 안 찾아진다(선택지: 그 컬렉션에 추가 / 새 컬렉션으로 바꿔 연결 / 이 작업용 사이드바 프로젝트를 새로 — `project.create`).
   - `elements.add` 는 이름 · 분류(character / location / prop) · 설명 한 줄 · 이미지(시트 원본 그대로, 장소는 메인 플레이트 한 장 — 역방향 컷용
     플레이트가 따로 있으면 그건 다른 엘리먼트로: `loc_motel_room` · `loc_motel_room_reverse`).
     이름은 짧은 영어 소문자 + 밑줄로 무엇인지 보이게 — `hero_mina`, `valet_oliver`, `lot_hotel_garage`, `prop_dashcam`(사용자 컬렉션들이 쓰는 방식).
   - 등록·연결은 과금·삭제가 없는 준비라 확인 카드 전에 해도 된다 — 무엇을 어느 컬렉션에 올리고 연결했는지 카드에 한 줄로 보여 주고,
     이름을 바꾸라고 하면 `element.update`.
   - 프롬프트에는 ACTIVE REFERENCES 의 역할 줄에 `@{이름}` 을 한 번씩, 동작·컷 문장은 사람 이름·물건 이름으로(`seedance-prompting.md` 2절).
     dry-run 이 지금 프로젝트에 연결된 엘리먼트를 보여 주고, 없는 `@{이름}` 은 보내기 전에 멈춘다.
1. 작업 목록을 JSON 파일로 쓴다 (임시 폴더). 형식은 스크립트 머리말에 있다:
   `{"guide", "manual", "project", "billing", "defaults": {"model", "mode", "ratio", "duration", "resolution", "draft", "output_count", "generate_audio"}, "jobs": [{"name", "prompt", "refs": [경로 또는 {"path", "role"}]}]}`
   - `guide` 는 이 지침 맨 위의 **지침 버전** 그대로. 지침이 그 사이 바뀌었으면 스크립트가 "지침이 바뀌었다" 며 멈춘다 —
     start 를 다시 받아 읽고 바뀐 규칙대로 고친다(대화가 길어져도 낡은 지침으로 나가지 않게).
   - `manual` 은 2단계에서 읽은 **설명서 버전** 그대로. 없으면 스크립트가 먼저 설명서를 읽으라고 멈춘다.
   - 설정 키와 값은 설명서에 있는 것만. 레퍼런스 순서가 프롬프트의 `[Image N]`·`[Video N]`·`[Audio N]` 번호다
     (종류별로 센다). 첫·끝 프레임은 `role` 로. 2.5 는 `draft` 를 꼭 적는다 (빼면 앱 기본값 = 초안 480p).
   - **인물·장소·소품은 파일 대신 `@{이름}`**(0단계, 앱 26.10.305~). 앱이 그 엘리먼트의 이미지를 레퍼런스로 붙인다 —
     화면에서 @ 멘션한 것과 같다. 프로젝트에 컬렉션이 연결돼 있어야 하고, 레퍼런스→영상 · 영상 편집 모드에서만 된다.
     엘리먼트만 쓰면 `refs` 는 비워 둔다(파일 `[Image N]` 과 섞어 써도 된다 — 번호는 파일 refs 만 센다).
2. 먼저 확인만 한다 (아무것도 안 보냄, 비용 0) — 설명서가 그대로인지, 앱이 켜져 있는지, 열린 프로젝트(사이드바),
   과금 프로젝트, 그 프로젝트로 쓸 수 있는 모델:
   ```bash
   node "<플러그인 폴더>/scripts/send-to-seedance.mjs" <jobs.json> --dry-run
   ```
   - **"앱이 업데이트됐습니다"** 가 나오면 새 설명서가 함께 출력된다. 그걸 기준으로 설정을 다시 맞추고 **확인 카드를
     다시 보여 준 뒤**, jobs.json 의 `manual` 을 새 버전으로 바꿔 보낸다. 같은 내용을 버전만 바꿔 그대로 보내지 않는다.
   - "에이전트 연결 전 버전" 이 나오면 앱을 껐다 켜서 업데이트하게 하고, 그동안은 아래 "옮겨 적기" 로 한다.
   - 과금 프로젝트가 안 골라져 있으면 앱 설정 패널 맨 위 "프로젝트" 에서 고르게 한다. 에이전트가 고르지 않는다.
   - 고른 모델이 "이 과금 프로젝트에 권한이 없다" 고 나오면 보내지 말고 다른 모델을 묻는다.
3. 5단계 확인 카드에 **프로젝트(사이드바)와 과금 프로젝트**를 보여주고 답을 받는다. 그 두 이름을 jobs.json 의
   `project`·`billing` 에 그대로 넣는다 — 그 사이 앱에서 바뀌면 앱이 보내지 않는다.
4. 보낸다. 앱이 하나씩 받아서 보낼 때까지 기다리고, 하나라도 실패하면 거기서 멈춘다:
   ```bash
   node "<플러그인 폴더>/scripts/send-to-seedance.mjs" <jobs.json> --watch
   ```
   앱이 작성 칸을 잠깐 빌려 보내고 원래대로 돌려놓는다 — 사용자가 치는 중이면 멈출 때까지 기다린다. "보냄" 이 나오면
   곧바로 "앱에 생성 중 카드 ○개가 떴다"고 알린다. 동시에 진행 중인 영상은 3개까지라(하루 200개 — 사내 규칙 2)
   스크립트가 앞의 것이 끝나길 기다렸다가 다음 요청을 넣는다. 영상이 4개 이상이면 처음부터 백그라운드로 돌리고 진행만
   알린다. `output_count` 를 적어 두면 더 빨리 보낸다(안 적으면 최대 3개로 잡고 기다린다).
   보내는 순간 "앱이 업데이트됐습니다" 로 멈추면 2번의 처리와 같다(그 전까지 보낸 건 출력에 나온다).
5. 끝나면 짧게 보고한다 — 성공·실패와 이유(앱의 경고 문구가 그대로 나온다: 권한 없음, 레퍼런스 거절 등).
   영상 주소(24시간짜리)가 나오면 열어 보고 요청과 다른 점을 말한다. 나중에 상태만 볼 때: `--status <id>`.

`node` 가 없으면 `references/read-apps-without-node.md` 의 "Node 없이 시댄스로 보내기" 대로 한다.

**작업 정리 — 앱 안과 PC 폴더** (사용자 10/14 "폴더링은 자동으로 깔끔하게") — 작업을 시작할 때 한 번 정하고, 그다음은 에이전트가 맞춰 둔다.

- **어디에 둘지는 처음에 한 번 묻는다**(3단계 질문에 같이, 실제 이름·경로를 선택지로).
  - 시댄스: `projects.list` 의 그룹·프로젝트를 보고 — 예: "그룹 「THINKWARE」에 새 프로젝트 「호텔 발렛 2차」(추천) / 지금 열린 「…」 / 다른 프로젝트".
    사용자가 쓰는 그룹 이름(클라이언트·시리즈)은 그대로 쓰고, 「Project 14」 같은 기본 이름이나 다른 작업 컬렉션이 연결된 프로젝트에 쌓지 않는다.
  - PC 폴더: 사용자가 쓰는 자리(`D:\외주\<날짜> <클라이언트>\<편>`, `D:\연구\<날짜> <작업>`) 중 추천 하나 + 직접 입력. 프롬프트 북도 이 폴더에 둔다.
- **앱 안**: 그룹 = 클라이언트·시리즈, 프로젝트 = 편·작업, 컬렉션 = 그 편의 에셋(그 프로젝트에 연결, 이름은 「<클라이언트> <편>」 — 예: 「띵크웨어 호텔 발렛편」).
  새로 만들면 `project.create {"name", "group"}`(만들면서 열려 사용자 화면이 바뀐다 — 위 질문으로 받은 뒤) → `collection.create` → `elements.add` → `collection.bind`.
- **PC 폴더 구조**(그 작업 폴더 안):
  ```
  01_에셋/        엘리먼트로 올린 시트·플레이트 — 에셋 작업의 name 을 엘리먼트 이름으로(hero_mina_A.png)
  02_이미지/      장면 이미지·첫 프레임·스토리보드
  03_영상_초안/    시댄스 초안 — <작업 이름>_A.mp4 · _목록.tsv
  04_영상_본편/    1080p·4K 본편(OK 컷만)
  05_프롬프트/    보낸 작업 파일(jobs.json)·프롬프트 북
  _검수/          검수 페이지·저장본·회차.json(검수 회차마다 분류·메모)
  _컷목록.tsv     컷·테이크마다 상태(OK·보류·탈락·미정)·파일·카드·메모 — 검수 적용 때 새로 쓴다
  _작업설정.json   이 작업에서 사용자가 정한 것(예: 검수 끔) — 다음 대화·다른 에이전트도 읽는다
  ```
  분류가 끝나면 각 폴더(01~04) 안이 `OK/`(쓸 것) · `보류/`(다시 볼 것·고쳐서 다시 만들 것) · `탈락/`(안 쓸 것)로 나뉜다.
  폴더 바로 아래에 남은 건 아직 검수 전(미정)이다.
- **보내기 스크립트가 옮겨 준다** — 나노바나나 `--save-to "<작업 폴더>\01_에셋"`(또는 `02_이미지`)는 앱 저장 폴더에서 **복사**한다(원본은 앱
  갤러리라 그대로). 시댄스 `--save-to "<작업 폴더>\03_영상_초안"` 은 끝난 영상을 받아 다운로드 폴더에서 **옮긴다**. 둘 다 `<작업 이름>_A` 식
  이름과 `_목록.tsv`(어느 카드·원본에서 왔는지)를 남긴다. `--save-to` 를 주면 끝날 때까지 지켜본다(`--watch` 포함).
- 고치면 같은 자리에서 — v2·v3 폴더를 늘리지 않는다. 다시 만든 테이크는 같은 폴더로 받고, 밀려난 옛 테이크는 검수에서 `탈락` 으로 고른다.
  지우는 건 사람 몫이다(탈락/ 도 지우지 않고 둔다).
- 보낸 작업 파일(jobs.json)은 임시 폴더 말고 `05_프롬프트` 에도 남긴다 — 나중에 프롬프트 북·다시 만들기에 쓴다.

**검수와 분류 — OK · 보류 · 탈락** (사용자 10/14 "보류 컷이랑 OK 컷 분류는 잘 함?" · "OK 보류, 탈락 등등")

**검수는 기본으로 켜져 있지만 뺄 수 있다** (사용자 10/14 "검수 없이 하고 싶은 사람도 있잖아 — 한 번 말한 건 기억하고 안 하는 거지?")
- 사용자가 "검수 빼 · 검수 없이 · 페이지 필요 없어"라고 하면 그 자리에서 기억시킨다 — 다음 대화·다른 에이전트도 따른다:
  ```bash
  node make-review.mjs --review off                      # 이 PC 사용자의 모든 작업(기본 — "검수 빼"는 이걸로)
  node make-review.mjs "<작업 폴더>" --review off         # "이번 작업만"이라고 했을 때
  node make-review.mjs "<작업 폴더>" --review status      # 지금 어떻게 돼 있는지
  ```
  다시 켜면 `--review on`(작업 폴더를 주면 그 작업만 켬 — 작업 설정이 사용자 설정보다 먼저). 꺼져 있으면 make-review 가 페이지를 만들지 않고
  그렇다고 알려 준다 — 이번 한 번만 보자고 하면 `--force`.
- 꺼져 있을 때는: 결과를 `--save-to` 로 작업 폴더에 받기만 하고(폴더 바로 아래 = 미정 그대로), 채팅에는 몇 개가 어디에 왔는지와 요청과 다른 점만 한 줄로.
  검수 페이지 · 검수 회차 · "어떤 걸 다시 만들까요?" 없이 끝낸다. 사용자가 고치라고 하면 그때 7단계. 끈 걸 다시 묻지 않는다.
  끈 뒤 첫 보고에만 "검수 페이지는 꺼 둔 설정이라 만들지 않았다(켜려면 '검수 켜')"를 한 줄 붙인다 — 그다음부터는 붙이지 않는다.
  7단계의 "에이전트가 먼저 고칠 곳을 찾았으면 묻기"도 꺼져 있을 때는 하지 않는다(눈에 띄는 실패 — 형식이 틀렸거나 비어 있음 — 만 한 줄로 알린다).
- **자동으로 다시 만드는 루프는 원래 없다** — 검수를 켜 둬도 다시 만들기는 사용자가 고른 것만(7단계), 과금되는 건 확인 카드 뒤.

1. 결과가 여러 개면(테이크 A/B, 여러 컷) 결과를 받은 뒤 검수 페이지를 만들어 준다(검수가 켜져 있을 때) — `freewill_script("make-review")`:
   ```bash
   node make-review.mjs "<작업 폴더>" --title "<작업 이름>"      # → <작업 폴더>\_검수\검수.html
   ```
   컷마다 테이크가 나란히 있고, 테이크마다 OK(쓸 것) · 보류(다시 볼 것) · 탈락(안 쓸 것) 과 메모, 컷 메모, 보낸 프롬프트, 크게 보기,
   'OK 이어서 보기'가 있다. 사용자가 고르고 저장하면 다운로드 폴더에 `<작업 폴더 이름>_검수_<시각>.json` 이 생긴다. 채팅에 영상·그림을 늘어놓지 않는다.
2. 사용자가 "저장했어" 하면 가장 최근 저장본으로 적용한다:
   ```bash
   node make-review.mjs "<작업 폴더>" --apply "<다운로드>\<…>_검수_<시각>.json"
   ```
   파일이 그 폴더의 `OK/` · `보류/` · `탈락/` 으로 옮겨지고, `_컷목록.tsv` 와 검수 페이지가 새로 써지고, 저장본은 `_검수/` 에 복사된다.
   출력된 OK 영상 카드는 시댄스 앱에서도 채택(★)한다 — 출력에 나온 `--do card.star "@…_star_N.json"` 을 그대로 돌린다(과금 없음).
3. 그다음은 분류대로 — **OK** 는 본편(`card.final` 💰 — 확인 카드 뒤)·프롬프트 북의 채택, **보류** 는 메모를 읽고 7단계로 고쳐 다시 만들지
   묻고("어떤 걸 다시 만들까요?"), **탈락** 은 다시 만들지 않는다. 다시 만든 결과는 같은 폴더로 받아 같은 명령으로 페이지를 다시 만든다.
4. **회차** — `--apply` 할 때마다 한 회차가 `_검수/회차.json` 에 쌓인다. 다시 만든 페이지(2차 · 3차 …)에서는 지난 회차의 메모가 입력칸에서 빠져
   컷·테이크 아래 **'지난 피드백'**(회차 · 시각 · 그 뒤에 새 테이크가 왔는지)으로 읽기 전용으로 보이고, 입력칸은 비어 있다 — 반영한 피드백이 입력칸에
   계속 남아 있지 않게(사용자 10/14 "업데이트됐으면 전 피드백으로 넣어야 하는 거 아님? 계속 적혀 있던데"). 지난 회차 뒤에 받은 테이크에는 **새로**,
   처음 화면은 **볼 것**(새로 · 미정 · 보류)만 — 이미 OK·탈락으로 끝난 건 '전체'에서 본다. 에이전트가 따로 만드는 검수·결정 페이지도 같은 규칙으로.

**옮겨 적기** (시댄스가 26.10.304 전이거나, 사용자가 직접 넣겠다고 할 때) — 칸 순서대로 정리해 준다:
모델 / 모드 / 비율 / 길이 / 해상도 / 개수 / 오디오 / 레퍼런스 순서와 역할 / 프롬프트.

**시댄스 앱 기능** (앱 26.10.305 이상) — 생성 말고도 앱에서 버튼으로 하던 일을 명령으로 한다. 명령 목록과 인자는
설명서의 "명령"에 있다(앱이 낸 것이 정답). 결과는 JSON 으로 나온다:
```bash
node "<플러그인 폴더>/scripts/send-to-seedance.mjs" --do collections.list
node "<플러그인 폴더>/scripts/send-to-seedance.mjs" --do elements.add @<인자.json>
```
- 인자는 JSON 파일로 써서 `@경로` 로 넘긴다 — Windows PowerShell 은 명령줄의 큰따옴표를 깨뜨린다. 짧은 `{}` 는 그대로.
- **인물·장소·소품은 어셋 라이브러리로**(시댄스 0단계): `collections.list` → (없으면) `collection.create` → `elements.add`(이름·분류·설명·
  이미지 경로) → `collection.bind`(지금 프로젝트 — 다른 작업 컬렉션이 연결돼 있으면 먼저 묻는다). 그 뒤 프롬프트에서 `@{이름}`.
  같은 이름은 건너뛰니 다시 돌려도 안전하고, 고칠 때는 `element.update`.
- 결과 다루기: `cards.list`(최신순 · 상태 · 초안 여부) · `card.get` · `card.star`(채택) · `card.download`(다운로드 폴더에
  저장 — 경로가 나온다) · `card.cancel`(대기 중만).
- **과금되는 명령(💰 `card.final` 초안 → 1080p 본편, `card.regenerate`)은 생성과 똑같이 확인 카드를 받은 뒤에만.**
  동시 3개 · 하루 200개 한도도 생성과 같이 센다 — 자리가 없으면 스크립트가 기다렸다 보낸다.
- `billing.list` 는 과금 프로젝트별 영상 수·토큰·2.5/4K 권한(크레딧 대시보드의 숫자)을 보여 줄 때만 — 고르는 건 사람이 앱에서.
- `projects.list` · `project.open` · `project.create` 로 사이드바 프로젝트를 다룬다. 지우기(카드·엘리먼트·컬렉션·프로젝트)는
  명령이 없다 — 사용자에게 앱에서 지우라고 안내한다.
- 앱 창이 최소화돼 있어도 된다(26.10.305~). "화면 응답 없음" 이면 앱이 꺼졌거나 그 전 버전이다.

## 7. 이어서 고치기

"더 어둡게", "2번만 다시", "카메라를 더 느리게" 같은 요청이 오면 지난 설정과 프롬프트를 유지하고 바뀐 부분만
반영해서 5→6 을 반복한다. 매번 처음부터 다시 묻지 않는다.

결과를 열어 보고 에이전트가 먼저 고칠 곳을 찾았으면, 무엇이 문제인지부터 짧게 보여주고 5단계의 선택지 질문
("어떤 걸 다시 만들까요?")으로 고르게 한다. 고른 것만 다시 만든다.

프롬프트 북(8단계)을 이미 만든 작업이면, 고친 결과가 나왔을 때 "프롬프트 북에도 반영할까요?" 로만 묻고 같은 북을 갱신한다.

## 8. 프롬프트 북 — 컨펌 뒤 권장 (강제 아님)

사용자가 결과를 **확정**하면("이걸로 가자", 채택, 1080p 본편까지 받음) 한 번 권한다 — "프롬프트 북으로 정리할까요?"
북은 컷마다 쓴 프롬프트(복사 버튼)·설정·레퍼런스·결과(채택·본편)·메모를 HTML 한 장에 담고, 목차·컷 스트립(누르거나 끌어서
이동)·찾기·크게 보기로 돌아다니게 만든다. 나중에 다시 만들거나 넘겨줄 때 쓴다.

- 정리할 거리가 있을 때만 권한다 — 여러 컷·여러 장, 레퍼런스를 쓴 작업. 한 장짜리 시험·아직 고치는 중이면 묻지 않는다.
  "안 함"이면 그 작업에서는 다시 묻지 않는다. 사용자가 먼저 "북으로 정리" 라고 하면 언제든 만든다.
- **저장 위치는 매번 사용자에게 묻는다**(정리할지와 같이 한 번에, 실제 경로를 선택지로) — 에이전트가 정하지 않는다.
  작업 폴더가 정해져 있으면 `<작업 폴더>\05_프롬프트\` 를 추천 선택지로 둔다(6단계 "작업 정리").
- 검수 분류를 했으면 `_컷목록.tsv` 의 **OK** 를 채택으로 넣고(본편이 있으면 본편), 보류·탈락 테이크는 넣지 않는다.
- 먼저 **작업 흐름**을 알아보고 거기에 맞춰 구성한다 — 에셋 → 영상(R2V) · 이미지 한 장씩 → 영상(I2V, 첫·끝 프레임) ·
  글 → 영상(T2V) · 영상 → 영상(V2V, 편집·연장·블록아웃) · 이미지만. 컷마다 달라도 되고 섞여도 된다.
- 만드는 법·book.json 형식·흐름별로 채우는 법은 `references/prompt-book.md`.
  스크립트는 `<플러그인 폴더>/scripts/make-prompt-book.mjs`.
