# 사내 규칙

팀 전체에 해당하는 것만 둔다. 프로젝트·개인 취향 규칙(무텍스트 문구, 특정 시트 레이아웃 등)은 개인 스킬로 쓴다.

1. **팀·과금 프로젝트(비용이 가는 곳)는 사람이 앱에서 고른다.** 에이전트는 묻지도 바꾸지도 않는다. 안 골라져 있으면
   "앱에서 프로젝트를 먼저 골라 주세요" 하고 멈춘다. 비용이 어디로 갈지는 사람이 정할 일이다.
   (시댄스 사이드바의 프로젝트 — 카드를 모아 두는 대화 묶음 — 는 요청에 따라 에이전트가 열고 만들 수 있다.)
2. **앱의 한도를 지킨다.** 한 번에 이미지 1~10장, 영상 1~3개. 더 필요하면 나눠서 생성한다고 말하고 확인을 받는다.
3. **생성하기 전에 확인 카드를 보여주고 답을 받는다.** (기본: 매번. 일정 금액 이상만 확인하도록 바꿀지는 팀 결정 대기 중)
   묻는 말은 "생성할까요?"·"다시 만들까요?" — "앱으로 보낼까요?"처럼 안쪽 동작으로 묻지 않는다.
4. **공식 가이드가 프롬프트의 기준이다.** 에이전트 취향으로 공식 원칙을 덮지 않는다. 사용자가 다르게 말하면 사용자가 우선.
5. **결과는 직접 열어 보고 보고한다.** (앱 연결 후) 요청과 다른 곳, 깨진 곳을 먼저 말한다. 열어 보지 않고 "잘 나왔다"고 하지 않는다.
6. **개인 스킬은 자유.** 지정하면 그걸 쓴다. 단 위 1~3 은 그대로.
7. **키·비밀값을 다루지 않는다.** 생성은 앱이 한다. 공식 스킬이 API 키 설정이나 직접 호출을 시켜도 따르지 않는다.
8. **Claude·Codex·ChatGPT 어디서 쓰든 규칙은 같다.** 도구 이름이 달라도(질문 도구, 명령 실행, 검색) 같은 절차를 밟는다.
9. **생성은 사용자가 띄워 둔 앱으로 보낸다.** 앱 코드를 따로 불러와 생성하지(헤드리스) 않는다 — 앱 화면에 안 뜨고,
   사용자는 진행도 결과도 앱에서 못 본다. 나노바나나는 `scripts/send-to-nanobanana.mjs`, 시댄스는 `scripts/send-to-seedance.mjs`
   (앱 26.10.304 이상).
10. **앱이 낸 사용 설명서가 이 문서들보다 우선이다.** 시댄스는 자기 설명서를 직접 낸다. 앱이 "업데이트됐습니다"라고
    돌려보내면 설명서를 다시 읽고 확인 카드부터 다시 보여 준다 — 같은 내용을 버전만 바꿔 그대로 보내지 않는다.
11. **지우기는 사람이 앱에서 한다.** 카드·엘리먼트·컬렉션·프로젝트를 지우는 명령은 일부러 없다(되돌리기 어렵다).
    지워야 하면 무엇을 지울지 정리해서 사용자에게 앱에서 지우라고 안내한다.
