# 프롬프트 북 — 컨펌된 작업을 HTML 한 장으로

결과가 확정되면 그 작업을 **프롬프트 북**(HTML 한 장)으로 정리해 주겠다고 권한다. 강제가 아니다.
북에는 컷마다 쓴 프롬프트(복사 버튼), 설정, 레퍼런스, 결과(채택·본편), 메모가 들어가고
목차·컷 스트립(누르거나 끌어서 이동)·찾기·크게 보기로 돌아다닌다. 나중에 같은 걸 다시 만들거나 넘겨줄 때 쓴다.

## 언제 권하나

- 사용자가 결과를 **확정**했을 때 한 번 — "이걸로 가자", "좋아 확정", 채택(`card.star`), 1080p 본편까지 받음 같은 순간.
- 정리할 거리가 있을 때만 — 여러 컷·여러 장, 레퍼런스를 쓴 작업, 다시 쓸 만한 프롬프트. 한 장짜리 시험이나 아직 고치는 중이면 묻지 않는다.
- 같은 작업에서는 한 번만 권한다. "안 함"이면 다시 묻지 않는다. 사용자가 먼저 "북으로 정리" 라고 하면 언제든 만든다.
- 이미 만든 북이 있으면 새로 묻지 않고 **같은 북을 갱신할지**만 묻는다(아래 "고칠 때").

## 묻기 — 정리할지 + 어디에 저장할지

한 번에 묻는다. Claude 는 AskUserQuestion, Codex 는 `freewill_ask`:

```
freewill_ask(message   = "컷 11개 · 채택 14 · 본편 11 — 프롬프트·설정·레퍼런스·결과를 북 한 장으로 정리할 수 있어요",
             questions = [{ title: "프롬프트 북으로 정리할까요?", options: ["정리", "안 함"], default: "정리" },
                          { title: "어디에 저장할까요?",
                            options: ["<결과가 있는 폴더>\\<작업 이름>_프롬프트북.html",
                                      "바탕 화면\\프롬프트북\\<작업 이름>_프롬프트북.html"],
                            default: "<결과가 있는 폴더>…" }],
             note      = "다른 곳에 저장하려면 경로를 적어 주세요")
```

- **저장 위치는 매번 묻는다.** 에이전트가 정하지 않는다. 선택지에는 실제 경로를 그대로 보여 준다.
- 검수 분류를 했으면 **OK** 를 채택으로 넣고(본편이 있으면 본편), 보류·탈락은 넣지 않는다.
- 결과 파일과 다른 폴더에 저장하면 그림·영상이 북 옆 `<북 이름>_files` 폴더로 복사된다 — 폴더째 옮기거나 압축해 넘겨도 열린다.
  영상이 많아 복사가 부담스러우면 `--link`(복사 없이 원래 자리, 이 PC 에서만 열림)를 제안한다.

## 만들기

1. `freewill_script("make-prompt-book")` 로 받아 임시 폴더에 `make-prompt-book.mjs` 로 저장한다.
2. 아래 형식의 `book.json` 을 임시 폴더에 쓴다 — 대화에서 실제로 보낸 것 그대로.
3. 실행한다:
   ```bash
   node make-prompt-book.mjs <book.json> --out "<사용자가 고른 경로>.html"
   ```
4. 출력 줄(저장 경로 · 컷 수 · 복사한 파일 · 없는 파일)을 확인하고 사용자에게 경로를 알려 준다. "없는 파일" 이 나오면 무엇이
   빠졌는지 말한다. 열어 달라고 하면 그때 연다.

## 작업 흐름 — 어떤 작업이었는지 먼저 알아보고 맞춘다

북을 쓰기 전에 이번 작업이 어느 흐름이었는지 대화·jobs.json·앱 모드로 알아본다. 컷마다 달라도 되고 한 북에 섞여도 된다.

| 흐름 | 알아보는 법 | 북에 넣는 것 |
|---|---|---|
| **에셋 → 영상 (R2V)** — 인물·장소·소품 시트를 먼저 만들고 그걸 레퍼런스로 영상 | 시댄스 `multimodal_reference`(레퍼런스→영상), 프롬프트의 `@{이름}`·`[Image N]` | `refs` = 에셋 시트(그림 · 만든 이미지 프롬프트 · 역할). 어셋 라이브러리 엘리먼트면 `"element": true`. 컷 `refs` 에 그 컷이 쓴 에셋 |
| **이미지 한 장씩 → 영상 (I2V)** — 컷마다 첫(·끝) 프레임 그림을 다듬어 고른 뒤 영상 | 시댄스 `image_to_video_first`·`image_to_video_first_last`, 또는 레퍼런스 모드인데 프롬프트가 "Use [Image 1] as the first frame" | 컷 `frames` = 첫·끝 프레임마다 그 그림을 만든 이미지 작업(프롬프트 · 모델 · 테이크 · 채택). 그 아래 영상 프롬프트 · 결과 |
| **글 → 영상 (T2V)** | `text_to_video`, 레퍼런스 없음 | 컷 `prompt` · `results` 만 |
| **영상 → 영상 (V2V)** — 편집 · 연장 · 블록아웃 무빙 따라 하기 | `[Video N]` 레퍼런스(Omni 편집·연장, 블록아웃 영상) | 원본·블록아웃 영상을 `refs` 에(`"category": "video"`), 컷 `refs` 에 `{"name": "블록아웃 v9", "as": "[Video 1]"}` |
| **이미지만** — 나노바나나 콘티 · 키 비주얼 · 에셋 시트 | 영상 없이 나노바나나 결과 | 컷 = 이미지 작업, `results` = 그림. 에셋 시트만 정리하면 `refs` 만 |

- **섞인 경우가 흔하다** — 예: 첫 프레임은 한 장씩 만들고(I2V), 무게추는 엘리먼트로(R2V), 블록아웃 영상은 [Video 1](V2V).
  그대로 다 넣는다(`frames` + `refs`). 북이 컷마다 흐름 표시(이미지→영상 · 첫 프레임 · @엘리먼트 n · 영상 레퍼런스)를 붙인다.
- 흐름은 북이 짐작한다(`frames` 가 있으면 이미지→영상, 레퍼런스가 있으면 레퍼런스→영상 …). 다르면 컷에
  `"flow": "r2v" | "i2v" | "t2v" | "v2v" | "image"` 로 정한다.
- **이미지 프롬프트는 그림 파일에서 읽을 수 있다** — 나노바나나가 저장한 PNG 에는 보낸 프롬프트와 모델이 들어 있다.
  `frames` · `refs` · 이미지 컷의 `prompt` 를 비워 두면 북이 채택한(없으면 첫) 그림에서 읽어 채운다("그림 파일에서 읽음" 표시).
  대화에 보낸 원문이 남아 있으면 그걸 쓴다.
- `[Image N]` · `[Video N]` 번호는 보낸 레퍼런스 순서 그대로 `as` 에 적는다. 첫 프레임으로 쓴 그림은 `frames` 에 두고 `refs` 에 다시 넣지 않는다.
- 여러 편 · 여러 샷(예: 승강로 7초 / 엔딩 15초)은 `tabs` 로, 한 편 안의 장면 묶음은 `group` 으로.

## book.json

```json
{
  "id": "k-prologue",
  "title": "「K」 프롤로그",
  "subtitle": "Seedance 2.5 · 21:9",
  "notes": ["작업 전체에 해당하는 메모 한두 줄"],
  "style": { "title": "공통 스타일", "en": "모든 컷 앞에 붙인 공통 문장(있을 때만)", "ko": "" },
  "tabs": [
    {
      "id": "prologue", "title": "프롤로그", "sub": "11컷",
      "refs": [
        { "id": "hero", "name": "폰슈테른 박사", "category": "character", "element": true, "role": "주인공 — 40대 로켓 과학자",
          "images": ["D:/…/hero_sheet.png"], "note": "", "prompt": "이 시트를 만든 프롬프트(비우면 PNG 에서 읽음)" },
        { "id": "blockout", "name": "블록아웃 v9", "category": "video", "role": "카메라 무빙 기준", "images": ["D:/…/blockout_v9.mp4"] }
      ],
      "cuts": [
        { "id": "C01", "title": "건배", "summary": "한국어 한 줄 — 무슨 장면인지", "group": "01 건배",
          "settings": { "model": "Seedance 2.5", "mode": "레퍼런스→영상", "ratio": "21:9", "duration": 8, "resolution": "480p 초안" },
          "refs": ["폰슈테른 박사", { "name": "블록아웃 v9", "as": "[Video 1]" }],
          "frames": [
            { "role": "첫 프레임", "title": "GPT #1 채택",
              "settings": { "model": "GPT Image 2.5 선버스트", "resolution": "4K" },
              "results": [ { "file": "D:/…/frame_1.png", "label": "1", "adopted": true }, { "file": "D:/…/frame_2.png", "label": "2" } ],
              "prompt": "이 프레임을 만든 이미지 프롬프트(비우면 PNG 에서 읽음)" }
          ],
          "prompt": "보낸 영어 프롬프트 원문 그대로",
          "prompt_ko": "한국어 요약(선택)",
          "results": [ { "file": "D:/…/C01_v1.mp4", "poster": "D:/…/C01_v1.jpg", "label": "1차", "adopted": false, "note": "" },
                       { "file": "D:/…/C01_v3.mp4", "label": "3차", "adopted": true } ],
          "finals":  [ { "file": "D:/…/C01_1080p.mp4", "label": "1080p 본편" } ],
          "notes": ["보이는 메모(편집에서 쓸 구간 등)"],
          "memo": ["접어 두는 메모(검수 메모 등)"] }
      ]
    }
  ]
}
```

- **편이 하나면 `tabs` 없이** 맨 위에 `refs`·`cuts` 를 둬도 된다. 편·버전이 여럿일 때만 탭으로 나눈다(예: 본편 / 야간편).
- `id` 는 컷마다 바뀌지 않게 — 북을 다시 만들어도 사용자가 체크한 표시가 컷 id 로 이어진다.
- `group` 을 주면 같은 group 의 컷이 한 묶음 제목 아래로 모인다(장면·시퀀스). 없으면 그냥 순서대로.
- `prompt` 는 **보낸 원문 그대로**(영어). 다듬거나 줄이지 않는다. `prompt_ko` 는 확인 카드에 쓴 한국어 한두 줄이면 된다 —
  있으면 북 위쪽에 한·영 전환이 생긴다.
- `settings` 는 보이는 말로: 모델은 앱에 보이는 이름(예: "Seedance 2.5", "나노바나나 2.1"), 모드는 한국어. `duration` 은 숫자(초)
  — 컷이 둘 이상 길이를 가지면 개요에 타임라인이 생긴다. 키는 자유(`{"비율": "16:9"}` 처럼 한국어 키도 됨).
- `refs` 는 레퍼런스 `name`(또는 `id`), 표기가 있으면 `{"name", "as": "[Image 2]"}`. 시댄스 엘리먼트는 `@{이름}` 의 이름 그대로 —
  레퍼런스 쪽에 `"element": true` 면 북에 `@이름` 으로 보인다(그냥 파일 레퍼런스는 이름만).
- `frames` 는 이미지 한 장씩 만든 첫·끝 프레임(위 "작업 흐름" 의 I2V). 없으면 빼면 된다.
- 파일 경로는 **절대 경로**(상대 경로는 book.json 이 있는 폴더 기준). 그림이면 그대로, 영상이면 `poster`(첫 장면 그림)가 있으면
  준다 — 없으면 영상 첫 프레임을 보여 준다.

### 파일은 어디서 가져오나

- **나노바나나**: 컷 = 보낸 작업(jobs.json 의 `name`). `results` = 그 작업에서 나온 그림 파일(보내기 스크립트가 끝나고 알려 준 경로),
  사용자가 고른 것만 `adopted: true`. `settings` = 모델·해상도·비율·장수. 레퍼런스는 jobs 의 `refs` 그림.
- **시댄스**: 컷 = 클립. `results` = `card.download` 로 받은 파일(**24시간짜리 영상 주소는 쓰지 않는다**), 채택(`card.star`)한 것은
  `adopted: true`, `card.final` 로 받은 1080p 는 `finals`. 레퍼런스는 어셋 라이브러리 엘리먼트(이름 · 분류 · 설명 · 이미지 경로)나 보낸 레퍼런스 파일.
- **에셋(인물·장소 시트)만 정리**할 때는 `cuts` 없이 `refs` 만 채워도 된다.
- 영상에 쓴 에셋·프레임은 위 "작업 흐름" 대로 `refs`·`frames` 에 넣는다. 영상과 상관없는 이미지 작업(예: 포스터)만 따로 탭으로.

## 고칠 때 — 같은 북을 그 자리에서

- 이어서 고친 결과(2차·3차, 새 본편)가 나오면 북이 있는 작업에서는 "프롬프트 북에도 반영할까요?" 로만 묻는다.
- 같은 `--out` 경로로 다시 돌린다. book.json 이 없으면 **북 HTML 을 입력으로** 넣어도 된다(북 안에 데이터가 들어 있다):
  `node make-prompt-book.mjs "<북>.html" --out "<북>.html"` — 이건 그대로 다시 만드는 것이라, 바꾸려면 데이터를 고친
  book.json 으로 돌린다.
- 컷 id 를 바꾸지 않는다. 새 테이크는 그 컷의 `results` 에 덧붙이고 `label` 로 차수를 적는다.

## 넣지 않는 것

- 로그인 표·키·토큰, 과금 토큰 수나 비용(사용자가 넣자고 할 때만).
- 외부(광고주·클라이언트)에 넘길 북이면 내부 메모(`notes`·`memo`·결과 `note`)를 빼고 만든다 — 누구에게 줄 건지 사용자가
  말했을 때만 이렇게 한다.
