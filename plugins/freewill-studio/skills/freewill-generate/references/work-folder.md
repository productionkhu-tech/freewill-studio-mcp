# 작업 폴더 · 작업 페이지 · 검수

폴더만 봐도 무엇을 봐야 하고 어디에 있는지 바로 알 수 있게 둔다. HTML 은 작업마다 하나만 두고 계속 고쳐 쓴다.
(사용자 10/14 "폴더링은 자동으로 깔끔하게" · 10/20 "OK·보류, 로케이션·프랍·인물로 나눠서 — 애매하면 물어보고",
"html 은 만들고 고칠 때마다 알아서 다뤄야", "html 늘려 가면 피곤함 — 한 html 에서 목차", "검수는 하나만, 저장 누르면 바로 저장")

## 1. 처음에 한 번 정한다

새 작업을 시작할 때 3단계 질문에 같이 묻는다(실제 이름·경로를 선택지로). 같은 작업을 이어 갈 때는 다시 묻지 않는다.

1. **프로젝트 폴더 · 프로젝트 코드** — 사용자가 알려 준 프로젝트 폴더(없으면 `D:\외주\<날짜> <클라이언트>\<편>` · `D:\연구\<날짜> <작업>` 중 추천 하나 + 직접 입력),
   그리고 파일 이름 맨 앞의 프로젝트 코드(예: ABC — 회사 규칙). 씬 · 컷 번호는 팀장이 나눠 준 콘티 번호를 쓴다.
2. **앱 자리**
   - 시댄스: 사이드바 그룹·프로젝트. 사용자가 이 작업용으로 만들어 둔 것이 있으면 그걸 쓴다.
   - 없으면 만들어 달라고 한다. 사용자가 "만들어"라고 하면 `project.create {"name","group","open":false}`(26.10.2002~ 화면 안 바뀜, 그 전 앱은 만들면서 화면이 바뀐다).
   - 나노바나나: 이 작업용 탭. 없으면 만들어 달라고 한다. 사용자가 "만들어"라고 하면 `send-to-nanobanana.mjs --create-tab "이름"`
     (앱 v2026-10-2001~, 화면 탭은 안 바뀐다).
   - 과금은 사람이 앱에서 고른다. 시댄스는 '프로젝트 코드'가 앱 전체에 하나(설정 패널 맨 위, 26.10.2004 — 사용자 결정), 나노바나나 팀·프로젝트는 탭마다
     고른다(앱을 켤 때마다 탭마다 한 번 확인 — 탭 옆 ! 나 우클릭 "팀·프로젝트…", 탭을 옮길 필요 없음).
   - 안 골라져 있으면 골라 달라고 한다. 에이전트가 고르지 않는다.
   - 프로젝트(과금)는 늘 골라져 있어야 하고, 생성마다 그 과금이 사용 기록(시댄스 트래커 시트 · 나노바나나 게이트웨이)에 맞게 찍히면 된다(사용자 10/20).
3. **시댄스 2.5 출력 형식**
   - **MOV**(편집용, 앱 기본) — 추천.
   - **MP4**(호환) — 1080p 는 HEVC 10-bit 다. MOV(4:4:4)는 일부 편집기·플레이어가 못 열고, MP4(4:2:0)는 더 잘 열린다.
   - 사용자가 미리 MP4 라고 했으면 묻지 않는다.
   - 정한 값을 jobs.json defaults 의 `output_format` 에 늘 적는다. 안 적으면 앱의 지금 설정을 따르기 때문에, 보내기 스크립트가 멈춘다.
4. **검수 화면을 쓸지 — 사람마다 한 번만**(사용자 10/22 "극 초반부에 물어보기 — 검수를 안 하는 사람도 있다")
   - 검수 화면 = 우리가 서버로 띄워 보여 주는 검수 페이지(5절). 앱 읽기(read-local-apps) 끝의 '검수 화면'이 "아직 안 정함"일 때만 첫 질문에 같이 묻는다:
     "결과를 검수 화면에서 볼까요?" — **늘 쓰기**(받을 때마다 검수 화면에서 OK·보류·탈락·메모를 고르고 저장) / **안 쓰기**(받은 그대로 컷 폴더에 OK, 채팅에 한 줄).
   - 답은 `make-review.mjs --review on|off` 로 이 PC 사용자 설정에 남긴다 — 다음 작업·다음 대화부터 묻지 않는다. 바꾸라고 할 때만 다시(6절).
5. **프롬프트 북을 늘 만들지 — 이것도 사람마다 한 번만**(사용자 10/22 "프롬프트북이랑 검수 둘다 처음에 선택")
   - 앱 읽기의 '프롬프트 북'이 "아직 안 정함"일 때만 4와 같이 묻는다: **늘 만들기**(OK 를 저장할 때마다 `05_프롬프트\<작업 이름> 프롬프트 북.html`
     을 사용자 샷리스트 스킬 양식 — 씬마다 체크 · 공통 스타일 접두 · 복사 버튼 · 채택 결과 — 으로 다시 씀) / **넘길 때만**(지침 8단계).
   - 답은 `make-review.mjs --book on|off`(이 작업만이면 폴더를 앞에). 검수를 안 쓰면 받은 것 모두가 북에 들어간다.
   - 검수 페이지(결과를 고르는 곳)와 프롬프트 북(쓴 프롬프트를 모은 정리본)은 다른 파일이다.

정한 것은 `<작업 폴더>\_작업설정.json` 에 남긴다(검수 화면은 사용자 설정). 다음 대화·다른 에이전트도 이 파일부터 읽는다.

```json
{ "title": "브랜드 광고 1편", "code": "ABC", "seedance_project": "2026.10.20 브랜드 광고", "nanobanana_tab": "브랜드 광고", "output_format": "mov" }
```

## 2. 폴더 — 씬 → 컷, 보면 뭘 봐야 하는지 바로 보이게

사용자가 알려 준 **프로젝트 폴더**(jobs.json `"work"`) 안에 씬 폴더 → 컷 폴더를 만들고(있으면 그대로) 거기에 받는다(사용자 10/21 · 회사 규칙).

```
<프로젝트 폴더>\
  <작업 이름>.html                 작업 페이지 하나(목차) — 이것만 열면 된다
  S010\                            씬
    C0010\                         컷 — 여기 바로 아래 = OK(쓸 것)
      ABC_S010_C0010_I001.png      이미지
      ABC_S010_C0010_V001_480.mov  영상 초안(480) — 이미지→영상이면 이미지와 같은 컷 폴더에 쌍으로
      ABC_S010_C0010_V001_1080.mov 본편 — 초안과 같은 번호, 꼬리만 _1080
      보류\                        다시 볼 것 · 고쳐서 다시 만들 것
    C0020\ …
  S020\ …
  01_에셋\인물 · 로케이션 · 프랍 · 참고    에셋은 씬·컷과 따로(이름 = 엘리먼트 이름, hero_mina_A.png)
  _검수\  _작업설정.json            목록·회차·서버 — 사람이 열 일 없음(전달 때 빼는 _ 폴더)
```

- **이름 = `<프로젝트 코드>_<씬>_<컷>_<I|V><번호>`** — ABC = 프로젝트 코드(jobs.json `"code"`, 한 번 적으면 `_작업설정.json` 에 남는다),
  S010 = 씬, C0010 = 그 씬 안의 컷, I = 이미지 · V = 영상, 번호 3자리. 씬 · 컷을 10 단위로 띄워 둬서 사이에 S015 · C0015 를 끼울 수 있다.
  - jobs.json 작업마다 `"scene": "S010"`, `"cut": "C0010"` 을 적는다. 에셋은 `"asset": "인물|로케이션|프랍|참고"`.
    어느 씬 · 컷인지, 어느 에셋 종류인지 애매하면 사용자에게 묻는다(콘티 번호 기준 — 팀장이 나눠 준 번호).
  - 번호는 그 컷에서 **이어서** 매긴다 — 다시 만든 것 · A/B안도 이어 붙인다(A안 1·2 → B안 3·4 → A안 다시 5). 어느 안인지는
    작업마다 `"version": "A"` 로 적어 목록과 작업 페이지에 남긴다(번호 구간으로 나누면 다시 만들 때 겹친다).
  - **영상 꼬리는 해상도** — 초안 `_480`, 본편 `_1080`(같은 번호). 본편은 `send-to-seedance.mjs --save-final <초안 파일> <본편 카드 id>` 로 받으면
    초안 옆에 같은 번호로 놓인다.
  - **여러 컷을 한 번에 뽑은 영상**(한 호흡을 한 덩어리 — seedance-prompting 5절)은 첫 컷 폴더에 첫 컷 이름으로 두고
    `"covers": "C0010~C0040"` 를 적는다 — 목록과 작업 페이지에 범위가 보인다. 씬을 넘으면 첫 컷의 씬 폴더에.
  - 이미지→영상 쌍은 같은 컷 폴더에 둔다. 번호는 꼭 같지 않다(한 이미지에서 영상 2판이면 V001 · V002 둘 다 I001 에서) — 어느 이미지에서
    나왔는지는 목록에 남긴다.
- **검수 뒤**: OK 는 컷 폴더 바로 아래 그대로, 보류는 그 안 `보류\`, **탈락은 지운다**(사용자 "탈락은 다운받을 이유가 없음" — 우리 사본만
  지우고 앱 원본은 나노바나나 저장 폴더 · 시댄스 카드에 남는다). 검수를 안 하면 받은 그대로가 OK 다.
- **어디서 왔는지는 `_검수\목록.tsv` 한 곳에**(작업 · 테이크 · 모델 · 원본 · 카드 · 범위 · 안 · 해상도) — 컷 폴더에는 전달할 파일만 둔다.
  전달은 씬 폴더째, `_` 로 시작하는 폴더 · 파일은 빼고.
- **판(版) 폴더를 만들지 않는다** — `_시트r2` · `06_다시작업_1019` · `output` · `v9` 같은 것. 다시 만든 것도 같은 컷 · 같은 에셋 폴더에 다음 번호로.
- **프로젝트 폴더 바로 아래에는** 작업 페이지 · 씬 폴더 · `01_에셋` · `_` 폴더만 둔다. 다른 HTML · MD · 비교 PNG · 임시 스크립트는 두지 않는다
  (에이전트 메모 · 시험 그림은 스크래치패드에).
- 지우는 건 탈락(검수에서 고른 것)뿐이다. 그 밖의 파일은 사람이 지운다.

## 3. 작업 페이지 — HTML 은 하나

```bash
node make-review.mjs "<작업 폴더>" --title "<작업 이름>"     # → <작업 폴더>\<작업 이름>.html (같은 파일을 고쳐 쓴다)
```

- **목차**: 한눈에(폴더마다 OK · 보류 · 미정 · 새로) · 검수(컷마다 테이크) · 보낼 것(다음에 보낼 레퍼런스 그림) · 기록(회차마다 피드백) · 프롬프트.
- **언제 갱신하나** — 사용자가 말하지 않아도 갱신하고, "작업 페이지 갱신 — ○○" 한 줄로 알린다. 서버로 열려 있으면 새로고침만 하면 된다.
  - 결과를 받았을 때
  - 분류했을 때
  - 다시 만들었을 때
  - 보내기 전(보낼 것)
- **다른 HTML 을 만들지 않는다**:
  - 계획 · 비교 · 고칠 목록 · 판별 검수 · 시험 결과 페이지를 따로 만들지 않는다.
  - 필요한 정보는 이 페이지의 섹션(보낼 것 · 기록)에 넣거나 채팅 한 줄로 한다.
  - 사용자가 바깥에 넘길 문서(프롬프트 북 · 보고서)를 달라고 할 때만 따로 만든다.

## 4. 보내기 전 — 레퍼런스를 그림으로 보여 준다

- jobs.json 에 `"work": "<작업 폴더>"` 를 넣고 dry-run 하면 `_검수\보낼것.json` 이 생긴다. 페이지 '보낼 것'에 작업마다 레퍼런스 그림이 뜬다.
  - 파일 레퍼런스는 그 파일을 그대로 보여 준다.
  - `@{엘리먼트}` 는 01_에셋 에서 같은 이름의 그림(OK 먼저)을 찾아 보여 준다.
- 확인 카드 전에 그 섹션을 보여 주고 "이 레퍼런스로 보낸다"를 한 줄 덧붙인다(사용자 10/20 "돌리기 전에 어떤 레퍼런스 쓸 건지 시각적으로").
- **레퍼런스는 넣을 때마다 따져 본다**(이미지 · 영상 모두 — 가져올 것 · 같이 끌려올 것과 막는 법 · 글이나 엘리먼트로 되는지). refs 마다 `why` 한 줄을 적고,
  페이지에는 그림 밑에 why 가 뜬다. why 가 없으면 보내기 스크립트가 멈춘다(`seedance-prompting.md` 2절 · `image-prompting.md` 2절).
- 보내고 나면 '보냄'으로 바뀌고, 보낸 jobs.json 이 05_프롬프트 에 남는다.

## 5. 검수 — 서버 주소 하나로, 저장은 바로

```bash
node make-review.mjs "<작업 폴더>" --serve     # 작업마다 하나 — 떠 있으면 그 주소 · '열기' 명령을, 꺼져 있으면 '띄우기' 명령을 알려 준다
```

- **여는 순서**(이 스크립트는 다른 프로그램을 실행하지 않는다 — 커넥터 통신 검사):
  1. `--serve` 가 "꺼져 있다"면 출력의 **띄우기** 명령을 그대로 돌린다. Windows 는 `explorer.exe "<…>.vbs"` — 숨은 창으로 떠서 에이전트 대화가 끝나도 꺼지지 않는다.
  2. `--serve` 를 한 번 더 돌린다. "떠 있음"이 나오면 출력의 **열기** 명령(`explorer.exe "http://127.0.0.1:…/"`)으로 사용자 브라우저에 연다.
  3. 그래도 안 뜨면 출력 괄호 안의 명령을 백그라운드로 돌린다(그 대화가 끝나면 같이 꺼진다).
- 사용자가 테이크마다 OK · 보류 · 탈락과 메모를 고르고 **저장**을 누르면, 그 자리에서 OK 는 컷 폴더에 그대로, 보류는 `보류\` 로 옮겨지고
  탈락은 지워진다(앱 원본은 앱에 남는다). 회차는 `_검수\회차.json` 에 남는다. 다운로드 JSON 은 없다.
  (씬·컷 배치 전의 예전 작업은 폴더 안 `OK\` · `보류\` · `탈락\` 으로 옮기던 그대로 둔다.)
- **한 묶음(컷 · 에셋)에서 OK 를 고르면 나머지 미정은 '고르지 않음'(탈락)으로 표시**되고 저장할 때 정리된다 — 남길 건 보류로(사용자 10/22
  "OK 했고 저장까지 했는데 잔여가 왜 있어"). 새로 받은 테이크는 보기 전이라 건드리지 않는다. 바뀐 것 없이 다시 저장하면 회차는 그대로다.
- `00_` 로 시작하는 폴더(원본 · 비교 영상)는 '보기만' 칸에 뜬다 — 고르지 않고, 볼 것에 세지 않는다. 검수할 결과는 씬·컷 · 01_에셋 에 둔다.
- 검수 파일(`_검수\회차.json` 등)을 손으로 고치지 않는다 — 정리가 필요하면 페이지에서 고르고 저장한다(손으로 쓰면 페이지와 어긋난다).
- 사용자가 "저장했어"라고 하면 마지막 회차를 읽고 다음 할 일을 묻는다.
- 서버가 꺼져 있을 때 페이지를 파일로 열면 저장은 다운로드 JSON 으로 받는다. 이때는 `node make-review.mjs "<작업 폴더>" --apply "<저장본>"` 으로 반영한다.
- 서버는 45분 동안 아무도 안 열면 스스로 꺼진다. 다시 볼 때는 `--serve` 부터 — 같은 작업은 같은 주소를 다시 쓴다.
- **회차** — 다시 만든 페이지(2차 · 3차 …)는 이렇게 보인다:
  - 지난 메모는 읽기 전용 '지난 피드백'(회차 · 시각 · 그 뒤 새 테이크)으로 내려가고, 입력칸은 비어 있다.
  - 새로 받은 테이크에는 '새로'가 붙는다.
  - 처음 화면에는 '볼 것'(새로 · 미정 · 보류)만 나온다.
- **그다음은 분류대로**:
  - **OK** → 본편(`card.final` 💰, 확인 카드 뒤)으로 간다. 출력에 나온 `card.star` 명령으로 앱 카드에 채택(★)을 켠다.
  - **보류** → 메모대로 고쳐 다시 만들지 묻는다("어떤 걸 다시 만들까요?").
  - **탈락** → 다시 만들지 않는다.
- 자동으로 다시 만드는 루프는 없다. 다시 만드는 건 사용자가 고른 것만이고, 과금되는 건 확인 카드 뒤에만 한다.

## 6. 검수 화면 켜기 · 끄기 — 처음에 고른 것을 기억

```bash
node make-review.mjs --review on|off                   # 이 PC 사용자의 모든 작업(1절 4 의 답, "검수 켜 · 빼")
node make-review.mjs "<작업 폴더>" --review off         # "이번 작업만"
node make-review.mjs "<작업 폴더>" --review status      # 지금 어떻게 돼 있는지("아직 안 정함"이면 사용자에게 묻는다)
```

- 작업 설정이 사용자 설정보다 먼저다. 꺼져 있으면 make-review 가 페이지를 만들지 않고 그렇다고 알려 준다. 이번 한 번만 보려면 `--force`.
- 아직 안 정했으면 켬으로 치되(페이지를 만든다) make-review 가 "사용자에게 한 번 물을 것"을 알린다.
- **꺼져 있을 때 하는 일**:
  - 결과를 종류 폴더에 받기만 하고, 채팅에는 몇 개가 어디에 왔는지와 요청과 다른 점만 한 줄로 알린다.
  - 검수 회차도, "어떤 걸 다시 만들까요?"도 없다. 눈에 띄는 실패(형식이 틀렸거나 비어 있음)만 알린다.
  - 끈 뒤 첫 보고에만 "검수 페이지는 꺼 둔 설정이라 만들지 않았다(켜려면 '검수 켜')"를 한 줄 붙인다.
